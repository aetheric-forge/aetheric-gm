# v0.1 milestone — private rules package campaign setup

Version 0.1 establishes the first complete rules-enabled campaign journey:

```text
Sign in
  -> manage an SSH credential in the user profile
  -> create or edit a campaign
  -> load and validate a rules package from an SSH Git repository
  -> pin the installed package to an exact commit
  -> select one ruleset by ID and version
  -> open and later reopen the campaign workspace from the local cache
```

The milestone is complete when an authenticated user can perform that journey with a private repository without exposing key material, executing repository code, or contacting Git during an ordinary campaign reopen.

## Included

- existing campaign creation and editing;
- a local user profile keyed by authenticated identity;
- encrypted private SSH credential management;
- verified SSH host identity;
- public or private SSH Git acquisition initiated from the Campaign editor;
- staged validation and atomic user-scoped package installation;
- exact commit provenance;
- campaign ruleset selection;
- offline reopening from the managed package cache;
- graceful rules-neutral behavior when a package is unavailable.

## Deferred beyond v0.1

- HTTPS Git credentials and tokens;
- automatic or scheduled package updates;
- local-directory package installation as a product surface;
- package removal and richer lifecycle management;
- campaign or character migration between ruleset versions;
- package-inclusive export;
- executable DLL extensions;
- multiplayer and shared credentials;
- a separate Workspace aggregate.
